## Architecture

### Dual Deployment Target
This app supports two deployment presets via `NUXT_NITRO_PRESET`:
- **node-server**: Traditional Node.js deployment with persistent connections
- **cloudflare-module**: Cloudflare Workers with hyperdrive, KV, and R2

The preset affects:
- Database connections (pool vs hyperdrive)
- Caching (Redis vs Cloudflare KV)
- File storage (local/R2 vs R2 only)
- Auth instance management (singleton vs per-request)

### Server Layer Structure

**`server/utils/`** - Core utilities and singletons
- `auth.ts` - Better Auth instance with Stripe/Polar plugins, OAuth providers
- `db.ts` - Drizzle ORM connection (pattern: singleton for node-server, per-request for CF)
- `drivers.ts` - Postgres pool, Redis client, Resend instance, cache abstraction
- `runtimeConfig.ts` - Centralized config generation (uses dotenv for CLI commands)
- `stripe.ts` / `polar.ts` - Payment provider integrations

**`server/api/`** - API route handlers
- `auth/` - Better Auth endpoints (auto-generated)
- `admin/` - Admin CRUD operations
- `file/` - File upload/management endpoints

**`server/database/schema/`** - Drizzle schema definitions
- `auth.ts` - Generated by Better Auth (use `npm run auth:schema` after config changes)
- `auditLog.ts`, `file.ts` - App-specific tables
- `index.ts` - Schema barrel export

### Auth Flow
Better Auth is configured with:
- Email/password with verification
- GitHub & Google OAuth
- Stripe & Polar subscription plugins
- Account linking enabled
- Audit logging on all auth events
- Session stored in Redis/KV secondary storage

### Payment Integration
- Provider selected via `NUXT_PAYMENT` env var (stripe or polar)
- Webhooks handled in `server/api/`
- User subscription status syncs to `user.polarCustomerId` or Stripe equivalent

### Environment Variables
All runtime config is centralized in `server/utils/runtimeConfig.ts`. When adding new env vars:
1. Add to `.env.example`
2. Add to `generateRuntimeConfig()` function
3. Access via `runtimeConfig.yourVar` (server) or `useRuntimeConfig()` (app)

### File Storage
Abstracted via `server/services/file/` supporting:
- `r2` - Cloudflare R2 (default)
- `local` - Local filesystem with public assets serving
- Rate limiting on uploads configurable via `fileManager.uploadRateLimit`

- `no-console`, `no-debugger` - Console output is used intentionally
- `vue/max-attributes-per-line` - Set to warn only
